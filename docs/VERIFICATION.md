# v0.4.1 验证

日期：2026-10-17。最低兼容目标 3.2.1（745）；旧版与当前版 Loon 真机回归待完成。

## 自动化

99 项测试及构建/语法检查通过。本次新增旧版入口全部 17 项命名绑定、移除新语法、字符串参数与特殊字符的完整双向四轮回归，并确认运行时版本日志。VM 模拟 $loon 字符串不是旧版 Loon 运行时验证。

以下测速引擎回归继续通过：保留固定分块的下载、上传、Range、Bytes 回执、预算、预热排空、未知在途、协议匹配与 HTML 转义回归；新增自适应和恢复验证：

- 单路 64 KB 起步、预热预算最多 1 MB，双向 compare 四轮不重叠，全部尝试不超总预算。
- 动态分块、150ms 错峰、临近截止缩块，聚合吞吐仍用实际统一墙钟。
- 高延迟快速线路逐步加大载荷，避免固定短时长目标卡在小块请求；八路完整响应载荷上限约 4 MB。
- 大上传块超时、并发大块预热丢失回调两类负载模型；前者可在明确结束后有限恢复，后者通过降低预热负载避开模型触发条件。模型不是用户真实网络根因重建。
- 任意负载都不回调时仍停止；晚回调不改变结果，不追加上传/下一轮，不虚构成功。
- HTTP 403/429、错误 Range、非法 Bytes 不恢复；持续网络失败有方向级一次硬上限。
- HEAD/预热/正式阶段的兼容回退；HTTP2 Protocol error 的实际故障类型；恢复字节与耗时不计成功新阶段速度但计总预算。
- 恢复后真实并发与 HTTP 版本留记录；跨 HTTP 版本不计算比较倍数。
- 模拟完整 Loon $httpClient 层，H2/H1 参数、Uint8Array 上传、恢复及诊断均可用，$done 只执行一次。

## 继承的 v0.4.0 真实请求证据

以下为 v0.4.0 实测记录，本次仅修改配置兼容与版本日志，未重复远端请求。测速核心除版本字段外保持一致。每次远端完整冒烟总请求数据上限 4 MB；Node 使用 keep-alive H1 或 HTTP2 客户端。以下只验证协议和流程，不代表 Loon、代理节点或线路带宽。

| 流程 | 结果 |
| --- | --- |
| 本地 H1：HEAD 不带 Accept-Ranges、合法 Range、完整 POST + Bytes | 双向单路/4 路流程与预算通过 |
| Apple auto / H2 | 下载与上传、单路/4 路及预热全部成功，Bytes 校验通过 |
| Apple 固定 H1 | 双向完整流程与 Bytes 校验通过 |
| CF 初次 H2 | 当前系统网络返回 Protocol error，暴露兼容错误分类缺项 |
| CF auto，补上协议错误分类后 | 每个方向一次 H1 恢复，随后单路/4 路下载上传成功；没有换源或扩大总预算 |

不能把本机 CF 可恢复推广成所有节点已修复，也不能从一次 HTTP2 错误判断服务全局不可用。
